# 自贡彩灯节 · 售票主机后台服务
## 票务系统推送接口对接规范（对齐技术方案 v2.4.1）

> 适用范围：景区票务系统（上游）向「售票主机后台服务」单向推送售票状态。
> 核心原则：**单向推送**——票务系统只 POST 数据给后台，后台绝不向票务系统下发任何指令。

---

### 1. 传输与地址

| 项 | 值 |
|----|----|
| 协议 | HTTP / JSON（`Content-Type: application/json`） |
| 方法 | `POST` |
| 路径 | `http(s)://<后台地址>/api/ticket/push` |
| 鉴权 | `X-Push-Token` 请求头（生产必带） + 来源 IP 白名单 |

---

### 2. 通用报文约定

- 字段命名 `snake_case`，编码 UTF-8。
- 每条消息必含 `type`（消息类型）与 `session_id`（会话号，由 `session/create` 返回）。
- 公共字段（建议在每类消息中都带，便于全链路追踪与去重）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 见第 4 节七类取值 |
| `session_id` | string | 是* | 会话号（首条 create 之后） |
| `order_id` | string | 否 | 订单号 |
| `ts` | datetime | 否 | 票务系统事件时间戳 |
| `seq` | int | 否 | 推送序号，用于去重与乱序检测 |

> *`session/create` 是独立接口（`POST /api/session/create`，无需 `session_id`），返回 `{session_id, ...}`。

---

### 3. 响应结构

后台统一返回：

```json
{ "code": 0, "message": "ok", "state": "S6", "page": "P-3", "ok": true }
```

| code | 含义 | 票务系统处理建议 |
|------|------|------------------|
| `0` | 成功，状态机已迁移 | 继续下一步 |
| `208` | 幂等拦截（重复事件已忽略） | **安全忽略**，不重复下单/扣款/打印 |
| `409` | 门禁拒绝（阶段不允许该事件/顺序错） | 按 `message` 提示，必要时等待前端引导 |
| `422` | 字段校验失败 | 检查报文格式 |
| `401` | token 无效 | 检查 `X-Push-Token` |
| `403` | 来源 IP 不在白名单 | 将来源 IP 加入后台 `ticketing.allowed_sources` |

---

### 4. 七类推送消息

#### ① `key_pressed` — 按键后的场次/票种

| 字段 | 必填 | 说明 |
|------|------|------|
| `key` | 是 | K1–K7（场次/票种按键） |
| `session_code` | 否 | 场次 `day`/`night` |
| `ticket_type` | 否 | `student`/`adult`/`senior`/`zero` |
| `qty` | 否 | 当前已录入票数 |
| `echo_ok` | 否 | 键位回读是否一致（false 触发重试计数，超 3 次告警） |

```json
{ "type":"key_pressed", "session_id":"S-20261027-0001", "key":"K6", "session_code":"day" }
{ "type":"key_pressed", "session_id":"S-20261027-0001", "key":"K4", "ticket_type":"adult" }
```

#### ② `id_card_read` — 刷身份证

| 字段 | 必填 | 说明 |
|------|------|------|
| `id_masked` | 否 | 脱敏证件号（前6后2） |
| `age` | 否 | 识别年龄 |
| `eligible_type` | 否 | 票种资格 `adult`/`student`/`senior` |
| `locked` | 否 | 实名是否已锁定（默认 false） |
| `card_count` | 否 | 已刷证件数（校验是否够票数） |
| `read_status` | 否 | `success`/`fail`/`timeout`（默认 success） |

```json
{ "type":"id_card_read", "session_id":"S-20261027-0001", "id_masked":"510302199001011234", "age":36, "eligible_type":"adult", "locked":true, "card_count":1 }
```

#### ③ `ticket_price` — 票价/票数（**推两次**）

| 字段 | 必填 | 说明 |
|------|------|------|
| `items` | 否 | `[{ticket_type,name,qty,unit_price,amount}]` |
| `total_qty` | 否 | 总票数 |
| `total_amount` | 否 | 总金额 |
| `remaining` | 否 | 该场次可售余量 |
| `order_id` | 否 | **第二次（最终订单）必带** |

- 第一次（报价，无 `order_id`）：用于需求确认阶段
- 第二次（最终订单，带 `order_id`）：用于锁定阶段

```json
{ "type":"ticket_price", "session_id":"S-20261027-0001", "total_amount":300, "remaining":12000,
  "items":[{"ticket_type":"adult","name":"成人票","qty":2,"unit_price":150,"amount":300}] }
{ "type":"ticket_price", "session_id":"S-20261027-0001", "order_id":"TZ20261027000123", "total_amount":300,
  "items":[{"ticket_type":"adult","name":"成人票","qty":2,"unit_price":150,"amount":300}] }
```

#### ④ `pay_result` — 支付结果

| 字段 | 必填 | 说明 |
|------|------|------|
| `status` | 是 | `success`/`fail`/`unknown` |
| `trade_no` | 否 | 支付流水号（success 时建议带，用于幂等落库） |
| `amount` | 否 | 支付金额 |
| `fail_reason` | 否 | 失败原因 |

```json
{ "type":"pay_result", "session_id":"S-20261027-0001", "status":"success", "trade_no":"4200001234202610270001", "amount":300 }
```

#### ⑤ `confirm_cancel` — 确认/取消按键

| 字段 | 必填 | 说明 |
|------|------|------|
| `key` | 是 | `confirm` / `cancel` |
| `effect` | 否 | `退格`/`清零`/`锁定`/`中止会话` |

```json
{ "type":"confirm_cancel", "session_id":"S-20261027-0001", "key":"confirm" }
```

#### ⑥ `print_command` — 打印指令

| 字段 | 必填 | 说明 |
|------|------|------|
| `qty` | 否 | 打印张数（默认 1） |
| `ticket_sns` | 否 | 票号列表 |
| `action` | 否 | `print`/`reprint` |

```json
{ "type":"print_command", "session_id":"S-20261027-0001", "qty":2, "action":"print" }
```

> ⚠️ **出票是否真正成功不采信本条指令**；实际出票张数/缺纸由机器人视觉通过 `/api/print/verify` 回传。

#### ⑦ `session_sold_out` — 场次售罄

| 字段 | 必填 | 说明 |
|------|------|------|
| `session_code` | 是 | `day`/`night` |
| `night_available` | 否 | 夜场是否仍有票 |

```json
{ "type":"session_sold_out", "session_id":"S-20261027-0001", "session_code":"day", "night_available":true }
```

---

### 5. 推荐推送顺序（标准散客全流程）

```
POST /api/session/create                 → 拿到 session_id
key_pressed(场次 K6, day)
key_pressed(票种 K4 ×N)                  → 录入票数
ticket_price(报价, 无 order_id)
confirm_cancel(confirm)                  → 需求确认
id_card_read ×N                          → 逐张刷证（card_count 递增）
ticket_price(最终订单, 带 order_id)
confirm_cancel(confirm)                  → 订单确认
pay_result(status=success, trade_no)
print_command(qty)
[后续由机器人 /api/print/verify 与游客 /api/session/ticket-taken 完成，非票务推送]
```

---

### 6. 幂等与重试

- 幂等键 = `session_id + type + 引用(证件号/流水号/seq)`；重复推送返回 `208`，**不产生重复订单、不重复扣款、不重复打印**。
- 票务系统可安全重发同一事件；后台自动去重。
- 收到 `409` 表示当前阶段不允许该事件（通常顺序错），请勿强行重试，按 `message` 提示处理。

---

### 7. 上线前检查清单

- [ ] 后台 `config/app.yaml` 已配置 `ticketing.push_token` 真实令牌，票务系统请求带 `X-Push-Token`
- [ ] 票务系统来源 IP 已加入 `ticketing.allowed_sources`
- [ ] `ticket_price` 在报价与最终订单阶段各推一次，最终订单带 `order_id`
- [ ] 每类消息带 `session_id` 贯穿全程
- [ ] 出票成功判定以 `/api/print/verify`（机器人）为准，不依赖 `print_command`
- [ ] 异常（支付不明/未出票/售罄等）按状态机返回码处理，必要时触发人工介入
